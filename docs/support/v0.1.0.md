# GabbaBoy v0.1.0 support ledger

This versioned ledger describes the current limited DMG preview. It contains stable scope and corpus facts only; it deliberately does not contain a future tag or source revision. `verify-support-ledger.py` checks the structured block below against the checked-in fixture manifests. A release workflow reads these same files from the trusted tag and emits a separate source-bound `support-ledger-v0.1.0.json` asset.

## Supported model and cartridge scope

- Model: deterministic, bootless DMG-CPU-B software profile. The boot ROM is skipped and startup values are emulator policy; no physical DMG-CPU-B qualification is claimed.
- Cartridge scope: 32 KiB ROM-only and the documented standard MBC1 matrix, including battery-backed RAM where supported. MBC1M, RTC, CGB, and other mappers are excluded.
- This is a bounded implementation and evidence statement, not a general game compatibility claim or an operating-system support floor.

## Evidence classes

- **Source-backed expectations:** documented behavior applied within the scoped deterministic model; revision-sensitive phases remain identified as assumptions.
- **Software regressions:** project-authored fixtures and tests that check implementation behavior.
- **Differential results:** the three named, derived Mooneye CPU/timer reporting closures. The upstream source reports DMG hardware passes, but the current runner's executed outcomes are software results and do not independently reproduce physical observations.
- **Physical hardware observations:** none for this release ledger.
- **Perceptual observations:** none claimed. SDL dummy output is software-path evidence only.

## Executed eligible corpus

Denominator: 3 eligible derived cases; 3 executed; 3 passed on the scoped software model. No compatibility percentage is inferred.

| Stable order | Case | Area | Executed result | Boundary |
|---:|---|---|---|---|
| 1 | `mooneye-acceptance-instr-daa` | CPU | pass | DAA register protocol and LD B,B result breakpoint |
| 2 | `mooneye-acceptance-timer-tim00` | timer | pass | Timer edge and guest register assertions |
| 3 | `mooneye-acceptance-timer-tim00-div-trigger` | timer | pass | DIV-reset falling-edge behavior |

No failed eligible outcomes are recorded for this denominator. The corpus manifest separately documents excluded PPU-dependent and boot-state-dependent candidates; those exclusions remain excluded rather than being counted as passes or failures.

## Authored fixtures and limits

Project-authored tracer, visible interactive demo, and MBC1 continuation fixtures have separate rights and digest manifests. They establish their named software protocols only. They do not establish broad game behavior, physical timing, physical persistence, or hardware equivalence.

Known issues and exclusions include: no boot-ROM execution; no CGB; no MBC1M, RTC, or other mapper; no broad game library qualification; no physical DMG observation; no analog/perceptual audio or video claim; and no signing/notarization claim unless separately verified for the final distributed bytes.
