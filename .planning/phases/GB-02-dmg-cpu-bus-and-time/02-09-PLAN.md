## Artifacts and Interface Contract

The implementation produces `gbb_input_event` (`at_half_dots`, `kind`, `value`), `gbb_queue_events`, `GBB_INPUT_STOP_WAKE`, `GBB_INPUT_SERIAL_EDGE`, a fixed 64-event instance queue, `gbb_diagnostic_record` (`time_half_dots`, `kind`, `pc`, `opcode`, `address`, `value`, `timer_state`), `gbb_run_ex`, caller-owned linear diagnostic output with per-call capacity and `diagnostic_count` in `gbb_run_result`. Core stop reasons include distinct `GBB_STOP_NO_PROGRESS`, `GBB_STOP_STOPPED`, `GBB_STOP_LOCKUP`, `GBB_STOP_UNSUPPORTED_BUS`, `GBB_STOP_OUTPUT_FULL`, plus budget and invalid-state outcomes. Host runner flags are `--manifest`, `--case`, `--suite` and `--receipt`; host statuses are pass/fail/timeout/unsupported and are separate from core stops. New focused test files are `tests/test_bus.c`, `tests/test_cpu.c`, `tests/test_control.c`, `tests/test_timer.c`, `tests/test_serial.c`, `tests/test_events.c`, `tests/test_diagnostics.c`, `tests/test_runner.c`; checked-in corpus lives under `fixtures/mooneye/` with `cmake/VerifyMooneye.cmake`.

The `GBB_STOP_HALTED_IDLE` result in 02-04 may distinguish a HALT budget spent on eligible device time; document its consumed ticks and keep it distinct from STOP/no-progress. All run operations preflight whole CPU operations, reserve output, and reject uint64 overflow before state mutation. The host alone retains a recent fixed 128-record diagnostic history across calls. Only source-qualified hardware results justify profile claims.
