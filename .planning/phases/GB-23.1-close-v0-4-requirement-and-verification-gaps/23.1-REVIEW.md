### CR-01: Unicode whitespace still fabricates accepted frontmatter structure

**Severity:** Critical  
**File:** tests/scripts/verify-planning-hygiene.py:316-318, 361-374, 384-400

**Issue:** The new yaml_source_lines correctly keeps NEL, U+2028, and U+2029 inside LF-bounded source lines, but downstream readers still use Python's Unicode-aware strip() and whitespace regexes for YAML syntax. For example, frontmatter_fields trims a non-break separator from a key before looking it up. If the required phase field is absent, a YAML key spelled phase<U+2028>: with the expected value is normalized to phase and can satisfy the checker; the duplicate-key scan does not recognize it because the colon is not immediately after the ASCII key. Separately, frontmatter_sequence and frontmatter_objects use line.strip() to identify root keys, so block-scalar content such as two spaces followed by U+2028 and unresolved_gates: can be mistaken for a root sequence; its indented scalar text can then supply the expected list items. The same root-key path can fabricate requirement_dispositions, and strip() on parsed values can erase a trailing non-break separator from a status or owner. These paths can let a report with missing or non-exact required frontmatter pass, contrary to D-199's field, sequence, disposition, and status/owner invariants.

The new causal fixtures prepend harmless text before each separator in with_root_block_scalar and with_combined_block_scalars, so they do not cover a separator that itself is consumed as whitespace at a key/value boundary. The direct helper cases check line preservation only; they do not exercise these readers' schema matching.

**Fix:** Keep Unicode non-break characters intact while parsing YAML tokens. Require exact column-zero root key lines for the schema's root sequences/objects, trim only YAML horizontal whitespace (ASCII space and tab) from keys and scalar values, and replace structural whitespace-regex matches with ASCII space/tab matches. Add production-CLI negative controls for a required key/value with NEL/U+2028/U+2029 at its boundary and for block-scalar content beginning with those characters before apparent root and nested fields; retain positive scalar-content twins.
