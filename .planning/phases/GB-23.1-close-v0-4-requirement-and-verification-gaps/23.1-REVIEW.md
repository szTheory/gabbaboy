### CR-03: ASCII-spaced duplicate root keys evade duplicate validation

**Severity:** Critical  
**File:** tests/scripts/verify-planning-hygiene.py:322, 341-347, 368-379, 389-408

**Issue:** frontmatter_fields trims ASCII spaces and tabs from each key before inserting it into a dictionary, so a YAML key written with whitespace before its colon aliases the canonical key. frontmatter_duplicates only recognizes keys whose colon immediately follows the key name. For example, a report with phase: wrong followed by phase : GB-22-composition-and-microtest-evidence overwrites the phase entry with the expected value, while the duplicate scanner sees only the first key. The report's expected-field check can therefore accept duplicate frontmatter. The same missed alias can follow a valid unresolved_gates: or requirement_dispositions: root: frontmatter_sequence stops at the next unindented line and frontmatter_objects stops parsing at it, while duplicate validation misses the alias, so contradictory duplicate root content is ignored. The special requirements map scanner handles whitespace aliases, but the other root readers do not.

**Fix:** Detect and reject duplicate YAML root keys after parsing the permitted plain-key spelling, including ASCII spaces/tabs before the colon, before any reader converts or consumes those keys. Require exactly one canonical root for protected sequences and objects as the map reader already does. Add causal CLI negatives for conflicting phase, gate-sequence, and disposition-object aliases in both root orders.

### CR-04: Unpaired quote stripping changes scalar values into accepted values

**Severity:** Critical  
**File:** tests/scripts/verify-planning-hygiene.py:322, 378, 401, 405

**Issue:** The field, sequence, and object readers call strip("\"'") after horizontal trimming. This removes any number or mixture of quote characters at either edge instead of recognizing a paired quoted scalar. A plain YAML scalar such as phase: GB-22-composition-and-microtest-evidence' has a trailing apostrophe in its actual value, but the reader removes it and produces the exact expected phase value. The same false normalization applies to expected sequence items and disposition status/owner values. The requirements-map reader correctly checks matching outer quote delimiters at lines 523-531, but the other four readers do not. Existing unmatched/mismatched quote controls at lines 2118-2121 and 2200-2201 cover the requirements map only.

**Fix:** Use one strict scalar decoder for these readers: retain plain scalar characters exactly, remove quotes only for a supported same-character paired quoted value, and refuse unmatched or mixed delimiters. Add production-CLI negative controls for required scalar fields, sequence values, and nested disposition values, with valid paired-quote twins.
