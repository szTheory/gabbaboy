## Summary

Reviewed the three changed non-planning files: the planning-hygiene checker, its CTest registration, and the UAT-closure checker. The new immutable reconciliation check has three false-pass paths: it does not verify criterion outcomes, and its parsers accept duplicate YAML keys and duplicate Markdown sections. These gaps can let contradictory historical evidence or owner handoffs pass the contract. Planning artifacts were read for context and excluded from the review-file count as required by the scope filter. No tests were run and no source files were changed.

## Critical Issues

### CR-01: [BLOCKER] Reconciliation accepts failed criterion results

**File:** `tests/scripts/verify-planning-hygiene.py:436-451, 492-505`
**Issue:** The report checker does not require the frontmatter `status` to be `passed` and only searches the first three goal-table rows for required words. It never parses each row's result cell. Changing a criterion result from `VERIFIED` to `FAILED` or `NOT VERIFIED` while retaining the expected terms still satisfies this check, so the report can contradict its claimed historical score and still pass `--stage report` and `--stage handoff`.
**Fix:** Require the expected report phase and `status: passed`, parse the goal table into criterion IDs and result cells, and require exactly criteria 1–3 with the approved passing status. Add a real-CLI negative control that changes a result cell while leaving the evidence wording intact and expects rejection.

### CR-02: [BLOCKER] Duplicate frontmatter keys can conceal contradictory gates or dispositions

**File:** `tests/scripts/verify-planning-hygiene.py:297-314, 318-342, 452-458`
**Issue:** `frontmatter_sequence()` returns the first matching sequence and `frontmatter_objects()` selects the first matching list without checking for another key later in the frontmatter. A report can therefore contain the expected `unresolved_gates` or Pending `requirement_dispositions` first, then a duplicate key with a reduced gate list or completed requirement dispositions; this checker still evaluates only the first list and passes. YAML consumers may reject duplicate keys or use the later value, so the checked interpretation is not reliable.
**Fix:** Reject duplicate top-level frontmatter keys and duplicate fields or requirement IDs, preferably with a YAML parser configured to reject duplicates. Add negative controls for a second conflicting `unresolved_gates` key and a second `requirement_dispositions` list.

### CR-03: [BLOCKER] Duplicate Markdown sections bypass report and handoff assertions

**File:** `tests/scripts/verify-planning-hygiene.py:345-353, 514-522, 556-568`
**Issue:** `markdown_section()` returns only the first section with a matching heading and ignores later sections with the same heading. The report and handoff checks use it for required no-go, limits, owner-handoff, and current-state facts. Adding a later duplicate such as `## Exact game no-go facts` or `## Owner Handoff` with contradictory claims does not affect the verdict, even though readers see both claims in the committed document.
**Fix:** Require each contract heading to occur exactly once and reject duplicates before checking its contents. Add negative controls that append a conflicting duplicate no-go and owner-handoff section.
