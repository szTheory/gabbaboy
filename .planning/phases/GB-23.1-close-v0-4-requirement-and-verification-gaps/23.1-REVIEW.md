## Critical Issues

### CR-01: [BLOCKER] Historical report requirements mapping can contradict its checked dispositions

**File:** `tests/scripts/verify-planning-hygiene.py:297-327, 490-516`
**Issue:** The actual Phase 22 report has both a `requirements` mapping (each requirement ID mapped to `pending`) and the checked `requirement_dispositions` sequence. The checker validates only the sequence; `frontmatter_duplicates()` tracks top-level keys and fields in sequence objects, but not keys or values in a nested mapping. Changing `requirements.RIGHTS-01` to `satisfied`, or adding a conflicting duplicate `RIGHTS-01` entry, leaves the exact Pending disposition list and `requirements_satisfied: []` intact, so `--stage report` still accepts a contradictory report.
**Fix:** Parse and require the nested `requirements` mapping to contain exactly the four original IDs, each Pending, with no duplicate keys; add CLI negatives for a changed status and duplicate mapping key.

### CR-02: [BLOCKER] Setext headings bypass the report and handoff section checks

**File:** `tests/scripts/verify-planning-hygiene.py:378-392, 549-555, 632-652`
**Issue:** The uniqueness and section readers recognize ATX headings only. Markdown also permits Setext headings such as `Exact game no-go facts` followed by `-----------------------`. A duplicate Setext section is not counted or treated as a section boundary; its contradictory text is included with the first section, whose checker only searches for required positive terms. A report or handoff can therefore contain a second visible conflicting section while the exact-heading count remains one and the contract passes.
**Fix:** Use a Markdown-aware heading parser or explicitly reject Setext headings for these contract sections, and add report and handoff CLI negatives that append a conflicting Setext heading.

## Warnings

### WR-01: [WARNING] CTest control minimum is below the 125-control floor

**File:** `tests/cmake/hygiene.cmake:82-85`
**Issue:** The planning-hygiene CTest currently requires only 116 controls. The self-test record for the reviewed source reports 125 controls, and the requested floor is 125; as configured, the CTest gate can lose up to nine controls and still pass.
**Fix:** Set `GBB_EXPECT_MIN_VALUE` to `125` and retain the assertion through `expect_exit.cmake`.
