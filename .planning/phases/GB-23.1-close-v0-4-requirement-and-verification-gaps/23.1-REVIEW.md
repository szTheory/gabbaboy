### CR-01: YAML block-scalar content can fabricate the required root map

**Severity:** Critical  
**File:** `tests/scripts/verify-planning-hygiene.py:479`

**Issue:** `frontmatter_mapping_pairs` uses Python `str.splitlines()` to split YAML frontmatter. YAML 1.2 treats U+2028 LINE SEPARATOR and U+2029 PARAGRAPH SEPARATOR as ordinary non-break characters, so a separator inside a block scalar does not end that scalar line. Python does split on U+2028, however. Replacing the report's actual `requirements:` map with this valid YAML block scalar makes the checker see a fake root map and accept its rows:

```yaml
attestation: |
  ordinary text<U+2028>requirements:
  FIXT-01: pending
  RIGHTS-01: pending
  DIAG-01: pending
  DIAG-02: pending
```

The actual YAML has no root `requirements` mapping, but the candidate's production `--check v04-reconciliation --stage report` CLI returned success for a disposable commit containing this mutation. This bypasses the report's fixed-schema and requirement-status check. YAML 1.2.2 specifies the non-break behavior in [§5.4, Line Break Characters](https://yaml.org/spec/1.2.2/#54-line-break-characters).

**Fix:** Split YAML frontmatter only on its actual line endings: normalize CRLF and bare CR to LF, then split on LF. Keep U+2028, U+2029, vertical tab, and form feed within the scalar line so they cannot synthesize root keys. Fail closed on frontmatter constructs outside the checker's supported subset.
