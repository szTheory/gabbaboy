### CR-01: An anchored requirements key bypasses root-alias rejection

**Severity:** Critical  
**File:** `tests/scripts/verify-planning-hygiene.py:459-460`

**Issue:** The root scan recognizes plain and quoted aliases, but it does not account for YAML node properties before a key. YAML 1.2.2 permits an anchor property before node content; its Example 6.23 includes an anchored mapping key with whitespace before the colon (`&a2 baz :`). A frontmatter line such as `&dup requirements : {FIXT-01: pending, RIGHTS-01: satisfied, DIAG-01: pending, DIAG-02: pending}` is therefore an anchored `requirements` root key. Here, `_frontmatter_root_key_is_alias` compares the text before the colon (`&dup requirements`) with `requirements` and returns false. The duplicate scanner also ignores the property-prefixed line. With the canonical map still present and correct, `frontmatter_mapping_pairs` accepts only that canonical map and the production report check can pass despite a contradictory second map or invalid duplicate-key frontmatter. See [YAML 1.2.2, §6.9 and Example 6.23](https://yaml.org/spec/1.2.2/).

**Fix:** Fail closed on YAML node properties for this protected root key. Since the checker only accepts a narrow frontmatter subset, validate root lines against allowed simple key spellings and reject anchor/tag-prefixed forms instead of trying to normalize arbitrary YAML syntax. Preserve pairs until duplicate validation.

### CR-02: `splitlines()` invents Markdown headings after Unicode separators

**Severity:** Critical  
**File:** `tests/scripts/verify-planning-hygiene.py:494`

**Issue:** Python's `str.splitlines()` treats U+2028 LINE SEPARATOR, U+2029 PARAGRAPH SEPARATOR, vertical tab, and form feed as line boundaries. CommonMark §2.1 defines line endings as LF, CR, or CRLF; those other characters remain inside the same line. A document can replace a required ATX heading with prose followed by U+2028 and `## Goal Achievement`. `visible_markdown_lines` splits that text into a synthetic heading, so both `markdown_heading_count` and `markdown_section` can accept a heading and body that are not Markdown blocks. The same shared path protects report and handoff headings and section bodies. See [CommonMark 0.31.2, §2.1](https://spec.commonmark.org/0.31.2/#characters-and-lines).

**Fix:** Normalize only CRLF and bare CR to LF, then split on LF explicitly. Keep all other Unicode separators as ordinary line content so they cannot create structural headings.
