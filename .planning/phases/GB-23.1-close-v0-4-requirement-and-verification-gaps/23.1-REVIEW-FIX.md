### CR-01 — Root requirement map and scalar syntax

`frontmatter_mapping_pairs` now requires exactly one column-zero `requirements:` field and reads only immediate two-space entries. It retains ordered key/value pairs until validation, rejects deeper mappings, missing or duplicate root maps, duplicate/missing/extra IDs, malformed scalars, and unmatched or mismatched quote delimiters. The four lowercase `pending` values must match the known IDs, the separate Pending/owner dispositions, and `requirements_satisfied: []`. Valid unquoted values and balanced single- or double-quoted values pass.

The existing production report CLI now has causal controls for a `metadata.requirements` lookalike without a root map, duplicate root and entry keys, missing/extra IDs, contradictory status, nested indentation, and unmatched/mismatched quotes. The matching-quote positive twin passes.

### CR-02 — Visible protected Markdown sections

`visible_markdown_lines` provides one line-preserving mask used by ATX heading counts, section extraction, and protected Setext detection. Fenced and indented code is hidden from headings, section bodies, global report facts, and required links. A fence closes only with its opening marker and at least its opening length; trailing whitespace is accepted, opposite/shorter markers do not close it, and an unclosed fence stays masked to document end. Continuation checks now use only the visible `Owner Handoff` body.

The existing production report/handoff CLI exercises hidden heading replacements on all protected report/handoff surfaces, coded-only bodies, hidden duplicates and fake boundaries, backtick and tilde fences, opposite and shorter false closes, an unclosed fence, indented code, visible closing hashes, existing Setext controls, and unrelated thematic-break positives. The controls verify that code cannot satisfy a section's required content or alter its visible boundary.
