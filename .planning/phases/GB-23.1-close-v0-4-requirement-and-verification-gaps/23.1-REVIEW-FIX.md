# Phase 23.1 Review Fixes

Date: 2026-11-14

## CR-01 — Fixed

The immutable Phase 22 report contract now requires the exact Phase 22 `phase` value and `status: passed`. Its Goal Achievement table must contain exactly criteria 1, 2, and 3, and every criterion result cell must be `VERIFIED`. The recognized result-column headings include the report's actual `Historical status` header, and the checker normalizes Markdown emphasis and backticks around result cells. The positive self-test fixture uses the actual header and bold `**VERIFIED**` cells. Disposable CLI controls reject wrong `phase`, wrong `status`, and a changed bold criterion result while retaining its evidence wording.

## CR-02 — Fixed

Report frontmatter validation now rejects repeated top-level keys and repeated nested fields. Requirement disposition IDs must also be unique. Disposable CLI controls confirm rejection of a duplicate `unresolved_gates` key, a repeated `requirement_dispositions` block, a repeated nested `status` field, and a duplicate requirement ID.

## CR-03 — Fixed

The checker requires each report contract heading exactly once and requires one `Owner Handoff` heading in STATE and the continuation plus one `Current State` heading in PROJECT. Disposable CLI controls confirm rejection of a duplicated report no-go heading and a duplicated current `Owner Handoff` heading.

## CR-04 — Fixed (second review of CR-01)

`markdown_section` and `markdown_heading_count` now recognize CommonMark ATX closing hashes. The report duplicate-no-go and current duplicate-Owner-Handoff controls use headings with closing hashes, proving those forms still count as duplicate contract headings.

## CR-05 — Fixed (second review of CR-02)

The current STATE handoff now rejects duplicate frontmatter keys with the distinct `v04-handoff-frontmatter-duplicate` failure. A real CLI negative control inserts a conflicting second `current_phase` value and confirms the handoff is rejected.
