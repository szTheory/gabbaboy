# Phase 23.1 Review Fixes

Date: 2026-11-14

## CR-01 — Fixed

The immutable Phase 22 report contract now requires the exact Phase 22 `phase` value and `status: passed`. Its Goal Achievement table must contain exactly criteria 1, 2, and 3, and every criterion result cell must be `VERIFIED`. The recognized result-column headings include the report's actual `Historical status` header, which is also used by the positive self-test fixture. Disposable CLI controls reject wrong `phase`, wrong `status`, and a changed criterion result while retaining its evidence wording.

## CR-02 — Fixed

Report frontmatter validation now rejects repeated top-level keys and repeated nested fields. Requirement disposition IDs must also be unique. Disposable CLI controls confirm rejection of a duplicate `unresolved_gates` key, a repeated `requirement_dispositions` block, a repeated nested `status` field, and a duplicate requirement ID.

## CR-03 — Fixed

The checker requires each report contract heading exactly once and requires one `Owner Handoff` heading in STATE and the continuation plus one `Current State` heading in PROJECT. Disposable CLI controls confirm rejection of a duplicated report no-go heading and a duplicated current `Owner Handoff` heading.
