## Narrative Findings (AI reviewer)

### CR-01: Requirements parser can validate keys under the wrong parent

**Classification:** BLOCKER (Critical)

**File:** `tests/scripts/verify-planning-hygiene.py:378-397, 583-590`
**Issue:** `frontmatter_mapping_pairs()` finds the first line whose stripped text equals `requirements:` rather than requiring the top-level field. It then treats every following two-space key as an entry. For example, a frontmatter block can put `requirements:` under `metadata:` and put the four IDs beside it at the same indentation; the helper returns the expected pairs even though the report has no root `requirements` map. `frontmatter_fields()` does not require that field, and `frontmatter_duplicates()` does not validate arbitrary nested mappings, so this malformed report can pass the new check while omitting the required top-level representation. The scalar cleanup at line 396 also strips unmatched quote characters, allowing malformed values such as `'pending` to compare as `pending`.
**Fix:** Anchor the lookup to the root field (`line == f"{key}:"`), parse only its immediate two-space mapping entries, and reject malformed quoting instead of stripping unmatched delimiters. Add production-CLI controls for a nested `metadata.requirements` lookalike with no root map and for an unmatched quoted status.

### CR-02: ATX headings inside code blocks count as protected sections

**Classification:** BLOCKER (Critical)

**File:** `tests/scripts/verify-planning-hygiene.py:400-416, 624-632, 709-716`
**Issue:** The new Setext scanner masks fenced and indented code, but the ATX section counter and section reader still scan raw lines. A report can remove a required visible heading and place `## Goal Achievement` (and its table) inside a fenced code sample: `markdown_heading_count()` counts that line, and `markdown_section()` uses it as the real section boundary. The corresponding protected-title checks therefore accept an example that is not a rendered section. The same raw-line counter is used for STATE, PROJECT, and continuation headings, so code examples can satisfy their heading-count checks as well. This defeats the ATX-only protected-heading contract and the stated requirement that code samples not be treated as protected headings.
**Fix:** Apply a shared visible-Markdown line filter to the ATX heading counter and section reader, masking fenced and indented code before counting headings or extracting protected sections. Retain controls showing that actual ATX headings with closing hashes pass and headings inside code do not satisfy required sections.
