      - a `receipt rejected: <text>` line gives that whole line;
      - an argparse `error: unrecognized arguments: ...` line gives `usage unrecognized` followed by the sorted `--flag` tokens without their values;
      - any other argparse `error:` line gives `usage <text after error:>`.
      A non-zero exit with no such line prints `judge differential undecidable` and exits 1. `--hosted RUN_JSON LOG` builds the same line from the hosted run. It prints `success` when the `rehearse-trusted-judge` job concluded success. Otherwise it takes that job's first failed step from RUN_JSON. It reads the exit code from that step's `Process completed with exit code N.` log line, and the key from that step's log lines by the same rule. LOG is `gh run view --log-failed` output. Each line there is prefixed `<job name>\t<step name>\t<ISO timestamp> `, and the exit-code line carries a `##[error]` marker. The checker splits off the two tab fields and the timestamp and strips the marker before matching. It considers only lines whose job field is `rehearse-trusted-judge` and whose step field is that failed step's name. A step field of `UNKNOWN STEP` is accepted only when the judge job has exactly one failed step. Lines from other jobs never decide the outcome, because corpus `full_ctest` is `continue-on-error` and its failure lines can appear in the same log. Any missing piece, or a job conclusion other than success or failure, is `judge differential undecidable` (exit 1). Its `--self-test` prints `judge-outcome controls pass controls=<n>` and is the CTest `judge_outcome_controls`. Its fixtures use the prefixed line shape, and its controls are:

      - a hosted log where an earlier `rehearse-corpus-and-support-sidecar` failed step carries its own `REJECT` and `Process completed with exit code 8.` lines before the judge step's lines must still yield the judge step's exit code and key;
      - its twin, holding only the other job's lines, is undecidable;
      - a judge-job line from a step other than the failed one is ignored;
