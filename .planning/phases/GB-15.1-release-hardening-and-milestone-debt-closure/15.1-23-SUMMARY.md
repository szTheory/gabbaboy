# Phase 15.1 Plan 23: Boundary-commit fuzz binding, restricted job-id token and dead review input Summary

Hosted fuzz verification now judges the release commit itself instead of the trusted checkout's moving HEAD, so a retry after main moved can reach publication; the job-id token stays on api.github.com, candidate-fuzz has an explicit bounded wait, and no workflow implies an accepted performance review.

## Accomplishments

- **WR-04 verifier (fbea5e2).** `verify_hosted` replaced its HEAD-equality check with a `git cat-file -e SHA^{commit}` test and the ReceiptError code `source-sha-not-in-history`. `validate_receipt` reads HEAD only inside `if not source_commit_only`, so the two commit-bound calls never do. Because the commit-bound path must not depend on the checkout, the dictionary digest and the seed fixtures are now read from the commit tree too (new `commit_blob`, `read_fixture(relative, commit)` and `expected_seed_records(commit)`); `source_manifest` already ran with `compare_worktree=False` there.
- **WR-07 (9c62aca).** `workflow_job_id` calls `api_base_url(test_fixture=False)` and ignores `GITHUB_API_URL`, catches `(OSError, ValueError, urllib.error.URLError)`, and validates the payload and each job record shape.
- **WR-04 workflow, IN-03 (89b638c).** candidate-fuzz lost the HEAD-equality block; the tag API check (now a multi-line brace guard) and the trusted verifier bind the source. Job env carries `CI_RUN_WAIT_ATTEMPTS: 90`, `CI_RUN_WAIT_SECONDS: 30`, `CI_RUN_WAIT_DEADLINE_SECONDS: 3000`, `CI_RUN_REQUEST_TIMEOUT_SECONDS: 60`, `HOSTED_POLL_SECONDS: 2700`; the loop breaks when `SECONDS - poll_start` reaches the deadline before each attempt, each lookup runs under `timeout`, and both BLOCKING LIMITATION messages state attempts and elapsed seconds. `timeout-minutes` went from 60 to 112. No wait was reduced. The review env entry, its comment and the `--review-regression` argument are gone from release.yml and release-rehearsal.yml (grep total 5 to 0). release-rehearsal.yml's two run-body `steps.corpus_run.outputs.run_nonce` expressions moved to step env and `check_rehearsal` now applies `_check_run_expressions`.
- **Policy.** `_check_fuzz_source_binding` (code `fuzz-source-binding`) parses candidate-fuzz run bodies, including command substitutions, and rejects any `git rev-parse HEAD`-style read and any `merge-base` or `--is-ancestor`. `_check_fuzz_wait_budget` (code `fuzz-wait-budget`) requires the five integer budget values and `timeout-minutes`, deadline at least attempts times interval, worst case (3000 + 60 + 30 + 2700 + 900 = 6690 s) at most `timeout-minutes` times 60 (6720 s), a loop-level deadline comparison followed by `break`, and a `timeout`-prefixed runs lookup. The tag API check and the `--poll-seconds "$HOSTED_POLL_SECONDS"` argument are now required calls.
