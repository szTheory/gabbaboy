# Phase 15.1 dense-review fixes

This follow-up closes two reproduced defects in the private borrowed-event-span path. It keeps the Phase 15.1 research contract: the adapter owns an immutable, bounded event span and cursor; the core validates it before mutation, borrows it for one run only, and clears the borrow on return. The public API and queue bounds remain unchanged.

## Finding 1: STOP wake at the run deadline

When a STOP wake arrived on the final half-dot of a run budget, the core consumed the complete budget and cleared the stopped state, then returned `GBB_STOP_NO_PROGRESS`. The shared stepper treats an unrecognized stop reason as stopped, so replay failed at an otherwise completed deadline.

**RED evidence:** before the repair, the isolated control exited 1 with `wake-at-deadline status=2 stop=8 end=0 actual=100`. The guest clock consumed the full 100 half-dots, but the run result was classified as stopped/no-progress.

**Change:** after a wake clears STOP, an exactly completed budget now returns `GBB_STOP_BUDGET`. A guest that remains stopped still returns `GBB_STOP_STOPPED`; a zero-budget poll remains `GBB_STOP_BUDGET`. The regression test also resumes the guest after an exact-boundary wake and requires the next CPU tick to execute.

**Controls:** `acceptance_drive_stop_wake_deadline` covers the shared driver at its deadline, direct private-run continuation, no-wake STOP behavior, zero-budget polling, and next-tick progress.

## Finding 2: borrowed-span input/output overlap

The private span validator already checked event order and timestamp bounds, cursor bounds, and overlap among the span descriptor, event array, cursor, and core instance. The audio and diagnostic wrappers did not check their writable outputs against those borrowed inputs. An internal caller could therefore pass a frame, trace, diagnostic, or frame-count output over pending input storage.

**RED evidence:** the pre-fix `acceptance_input_span_output_alias` control exited 1 and rejected `0/10` deliberately overlapping calls. The frame-count/span-descriptor case also demonstrated mutation: the wrapper zeroed `span.count` before validation.

**Change:** the private audio and diagnostic wrappers now use the existing overflow-safe `ranges_overlap` validator to reject any output range that overlaps the borrowed descriptor, event array, or cursor. Capacity multiplications are checked before constructing ranges. The audio wrapper performs these private-span checks before zeroing the output count. Public `gbb_run_audio` still follows its existing output initialization and validation order because it has no borrowed span.

The 10 rejection controls use aligned subranges of one safely allocated buffer. They cover partial event-array overlap by frame, trace, and diagnostic outputs; full output overlap with the span descriptor or cursor; and frame-count overlap with the descriptor or cursor. Each uses a positive run budget and requires `GBB_STOP_INVALID_STATE`, zero consumed time, and unchanged event bytes, cursor, and descriptor. The separate valid zero-budget span case requires the existing budget result and zero output count.

These alias tests exercise the private caller contract; they do not imply that supported callers currently alias buffers. The current stepper and diagnostic replay call sites keep their parsed event storage separate from their audio, trace, diagnostic, and count outputs.
