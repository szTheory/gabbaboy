# Phase 15.1 Plan 20: Shared STOP-resume rule and span output contract Summary

One `gbb_accept_stop_resumable` rule now drives both the main stepper and the runner's diagnostic replay (via the new `gbb_accept_diag_advance`), closing WR-03, with the two 16384-event limits statically linked (IN-04) and the borrowed-span `out_frame_count` zeroed only once it is proven outside the span (IN-06).

## Accomplishments

- **WR-03 (D1, D2).** `advance_to_span` and `gbb_accept_diag_advance` both call `gbb_accept_stop_resumable`. `replay_diag` now makes one `gbb_accept_diag_advance` call per window and passes its logical time as the guard origin, so the guard stays `(deadline - logical) / 4 + 1024` as at HEAD. `grep -c gbb_accept_run_diagnostic src/runner/acceptance.c` went from 2 to 0.
- **IN-04 (D3).** `stepper.c` carries a `_Static_assert` prefixed `accept event limit link:`. A ctest-time probe pair builds private copies of the sources: the violating tree uses a `16385u` script limit, the control tree is unmodified. Both libraries are `EXCLUDE_FROM_ALL`.
- **IN-06 (D4, D5).** `accept_span_count_is_outside` compares raw address ranges only and never dereferences the cursor or events. The count is zeroed once, after it and before `validate_accept_input_span`.
- **Alias test.** `acceptance_input_span_output_alias` derives its `rejected=N/12` denominator from `SPAN_OUTPUT_ALIAS_CASES`. It gained the `frame-count/events` and `frame-count/unvalidated-cursor` sub-cases, and the two frame-overlap sub-cases now require count 0.

## IN-06 contract carve-out

The only invalid returns that leave `*out_frame_count` untouched are a NULL count pointer, and a count whose storage overlaps or cannot be proven disjoint from the caller's span memory. An aliasing count is caller input, and writing it would be a partial mutation on a rejected call (AGENTS.md). This is part of the contract, not a deferred residual.
