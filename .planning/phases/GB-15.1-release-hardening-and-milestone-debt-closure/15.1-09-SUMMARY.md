# Phase 15.1 Plan 09: Safe retry recovery and bounded downloads Summary

**Retries decide from independently read live release state before any write, and the release source-archive downloads are streamed through a standard-library helper with hard byte, total-time and stall bounds.**

## Accomplishments

- **Task 1.** `--check-recovery` now takes a scope (`full` or `subset`), reads release, assets, tag and the release workflow's own run list, and hands them to `decide` with the workflow path and source SHA. It is wired into `publish-qualified-release` (full) and `attach-v02-evidence` (subset), each after a trusted `--inventory` of the bytes about to be attached and before the first upload. The publisher uploads exactly the names the decision lists as missing; the attacher attaches only decision-listed assets. The scratch directory is trapped in a subshell, and the previous `local status=$?` after a failing command (which skipped cleanup under `set -e`) is gone.
- **Task 2.** `download-release-artifact.py` enforces a streamed-byte cap that does not trust any header, a total and a stall deadline, bounded redirects, https only (http only to loopback behind a test flag), no credential beyond the first origin, and an output that is complete or absent. The curl floor note is accurate: curl 8.4.0 or newer already caps unknown-length bodies; the helper's value is the host-floor, time and cleanup guarantees.
- **Judge.** `verify-workflow-policy.py` gained 16 intended-defect controls (now 77 negative, 4 positive), the `unbounded-download` and `recovery-order` rejections, and an ordering check that the published-asset readback follows the publication transition.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Unchanged retry could never reproduce its final receipts**
- **Found during:** Task 1
- **Issue:** The publisher downloaded the whole draft, so an earlier attempt's `SHA256SUMS` and `release-receipt.json` were counted in the new sums and in the receipt's asset list, and the retry's receipts then differed from the attached ones.
- **Fix:** Receipts are built from the qualified inventory only; the recovery decision compares them to the attached bytes.
- **Files modified:** `.github/workflows/release.yml`
- **Commit:** `37a924f`

**2. [Rule 1 - Bug] Recovery counted any same-commit workflow run as a writer**
- **Found during:** Task 1
- **Issue:** The existing query listed every workflow run for the source SHA, so CI on that commit would block recovery, and a retry dispatch from a later main commit would be invisible.
- **Fix:** Query the release workflow's own runs and filter by path, source SHA and event.
- **Commit:** `37a924f`

**3. [Rule 1 - Bug] Blocking full-buffer read let a slow drip outlast the deadline**
- **Found during:** Task 2 (control hung until the harness timeout)
- **Fix:** `read1`, with the socket timeout set to the smaller of the stall and remaining total time before every read.
- **Commit:** `04181f3`

### Plan-shaped decisions

- The policy judge reader does not support `case`, so the workflow branches use `if/elif`.
- The candidate job runs the helper from a copy cut from the workflow revision (`git show "${GITHUB_SHA}:..."`), the same pattern it already uses for the gate; the manifest job runs it from the trusted checkout.

## Known Limitations (not closed, none marked pass)

- **Published-state retry in the workflow.** The decision returns `published-verified` and the CLI is controlled for it, but the publisher still refuses to start unless the release is a draft, so a retry against a published release stops rather than verifies. It never overwrites or re-drafts.
- **Early residual jobs.** The `candidate`, `candidate-macos`, `candidate-windows` and `candidate-platform-manifest` attachment points keep their existing exact-name and byte-compare refusals and are not behind the new decision. They are source-executing residual jobs named in Plan 08.
- **Fixture, not hosted.** The fake `gh`, local HTTP servers and policy mutations are fixtures. Nothing ran on GitHub, the API `path` field format was handled for an optional `@ref` suffix but not observed live, and the workflow endpoint pagination is capped at 100 runs. Plan 16 owns hosted reproduction.
- **Source-archive download only.** The helper covers the three source-archive fetches. `gh release download` calls (GitHub CLI) are unchanged.
