## SUMMARY coverage schema

Every plan summary uses this exact block shape, one entry per delivered capability. Populate real source-bound evidence and actual completed results. Use `unit`, `integration`, `e2e`, `automated_ui` or `other`; never use `ctest` as a kind, flow-style objects or inline comments.

```yaml
coverage:
  - id: RELEASE-CLAIMS
    description: "Concrete observable outcome established by the cited evidence."
    human_judgment: false
    verification:
      - kind: integration
        ref: "Actual command/result and immutable source or retained evidence reference."
        status: pass
```

The release checkpoint records authority for a one-way action, not a software deliverable requiring human judgment. Credential failures are handled only when observed. Do not invent gameplay, perception or document-reading UAT. Shared closure is generated and checked with `tests/scripts/verify-uat-closure.py`, always using `23-UAT-EVIDENCE.md` as the `--write` evidence input to generate `23-UAT.md`; never hand-write UAT. Plan 23-06 generates closure for completed release-evidence coverage without claiming Plan 23-08 is complete. Plan 23-08 first requires all nine completed summaries, then regenerates and validates/self-tests closure against that full set before final handoff. The shared tool checks existing summary coverage, so its success alone cannot prove that a missing future summary is complete. Boundary facts use their immutable boundary commits and never current-HEAD ancestry or live continuation assertions.

Phase 23 ends after qualification and closeout. The next stage is the owner-controlled v0.4 milestone audit through `/gsd-audit-milestone`; do not start it as part of these plans.
