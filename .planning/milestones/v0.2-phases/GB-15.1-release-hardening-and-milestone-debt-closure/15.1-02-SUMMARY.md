# Phase 15.1 Plan 02: Dense acceptance input delivery Summary

**Acceptance input now drains dense same-time spans through the existing bounded queue while keeping the frozen Libbet timing, frame and PCM results unchanged.**

## Accomplishments

- Added the private, one-run borrowed event-span and explicit cursor contract. The core validates the complete span before mutation, refills its existing 64-entry queue with due same-time events in order, and clears the borrow on return.
- Routed the shared acceptance stepper and diagnostic replay through the same core path. Custom `gbb_accept_drive` callbacks still use caller-managed batches capped at 64; public queue and serialized save-state formats are unchanged.
- Added direct controls for 0/1/63/64/65-event boundaries, equal timestamps, instruction-boundary carry, batching at 1 and 64, STOP wake, iteration guard and delivery failure.
- Added a standard-library CLI verifier. Its 67-event same-time Libbet START burst matches frozen T_hit, title/play-start/mid/hit frame digests, rolling frame digest and PCM digest. Removing START produces the expected predicate failure and a 1,990-byte bounded stall report; the isolated no-refill mutant also fails with `predicate-not-reached` and emits no success receipt.
- Updated the acceptance documentation with the span lifetime, parser bound and remaining public queue/callback limits.

## Decisions Made

- Drain all due events at a timestamp in script order before guest execution, with caller-owned explicit continuation between run calls.
