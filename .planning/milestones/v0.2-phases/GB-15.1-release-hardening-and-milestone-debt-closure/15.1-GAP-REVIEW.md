## Summary

(`gbb_accept_stop_resumable` / `gbb_accept_diag_advance` extraction, `accept_span_count_is_outside`, the
`_Static_assert` limit link) are behaviourally equivalent to the old code plus the intended fixes. I found no
regression in them. The job splits and step-scoped `GH_TOKEN` in `release.yml` hold up. I parsed every `gh` step
and every `${VAR}` used in the split steps and found no step that lost its token or an env variable, and
`verify-workflow-policy.py --check` and `verify-published-release-assets.py --self-test` pass on this tree.

One prior finding is only partly closed. The WR-04 fix (fuzz reader no longer compares HEAD with the source SHA)
decoupled subject identity from HEAD, but the workflow-contract check in `verify-v02-fuzz.py` still judges HEAD's

new verifiers. No prior WR-/IN- item was found to be wrongly fixed otherwise: WR-03 (replay/main STOP parity), IN-04,
IN-06, WR-01 (token scope and overlay), WR-05 and WR-06 are present and exercised by negative controls.

## Critical Issues

### GR-CR-01: Hosted fuzz verification judges the workflow contract against the trusted HEAD's `ci.yml`, not the release commit's (WR-04 fix incomplete)

**File:** `tests/scripts/verify-v02-fuzz.py:893-897` (with `verify_hosted` at 861-897 and `validate_receipt` at 570-640)
**Issue:** The WR-04 fix makes the subject the boundary commit S: the receipt is checked against S's commit tree
(`source_commit_only=True`, `commit_blob`, `source_manifest(compare_worktree=False)`). The campaign that actually
ran was S's `ci.yml` and S's `run-bounded-fuzz.sh`. `verify_hosted` then still calls
`check_workflow_contract(ROOT / WORKFLOW, runner_source=ROOT / "tests/scripts/run-bounded-fuzz.sh", ...)`. `ROOT`
is the trusted checkout at the moving HEAD, so the contract (Clang 18, ubuntu-24.04, 30-45 minute timeout, 60 s
explore route, artifact naming) is asserted on the wrong revision. This breaks the verdict in both directions:
- If S's `ci.yml` was weaker or non-conforming but main has since been fixed, the gate passes a campaign that never
  met the contract. The receipt only binds S's workflow digest; it does not prove S's text satisfies the contract.
  The `release.yml` comment cites this exact failure mode for a tag-frozen verifier.
- If main later changes `ci.yml` shape (job rename, timeout), a legitimate retry of an older release is rejected.
  That is the retry-after-main-moved scenario WR-04 was meant to fix.

The new tests (`moved_main_clone`) only add a marker file and the verifier on top of S, so `ci.yml` is identical at S
and HEAD and the divergence is never exercised. The "verdict identical at S and after main moved" control cannot
detect this.
**Fix:** Read the workflow and runner from S's tree when the commit-bound path is used, keeping the validator
(`SCRIPT`) as the judge from HEAD:
```python
workflow_text = commit_blob(expected_sha, WORKFLOW).decode("utf-8")
runner_text = commit_blob(expected_sha, "tests/scripts/run-bounded-fuzz.sh").decode("utf-8")
check_workflow_contract_text(workflow_text, runner_text, validator_source=SCRIPT)
```
Refactor `check_workflow_contract` to take text (or temp files written from the blobs). Add a moved-main fixture
whose HEAD `ci.yml` differs from S's, with a positive control (S conforming, HEAD non-conforming, accepted) and a
negative control (S non-conforming, HEAD conforming, rejected).

## Warnings

### GR-WR-01: `workflow_job_id` exception narrowing lets `http.client` errors crash the receipt producer

**File:** `tests/scripts/verify-v02-fuzz.py:342-345`
**Issue:** `except Exception` was narrowed to `(OSError, ValueError, urllib.error.URLError)`.
`http.client.IncompleteRead` (raised by `response.read(n)` on a truncated body) and
`http.client.BadStatusLine`/`ImproperConnectionState` derive from `http.client.HTTPException`, not `OSError`. A
transient truncated response now escapes as a traceback in `build_workflow_record` (called while producing the
receipt in the sanitizer job) instead of returning `job_id=None` as before. The new defensive-parse test does not
cover transport errors raised from `read()`.
**Fix:** `except (OSError, ValueError, http.client.HTTPException):` (add `import http.client`; `URLError` is
already an `OSError`), and add a recorder case whose `read()` raises `http.client.IncompleteRead`.

### GR-WR-02: `gbb_accept_diag_advance` guard underflows when `guard_origin_half_dots > deadline`; the documented precondition is unenforced

**File:** `src/accept/stepper.c:37-41` (contract in `src/accept/gbb_accept.h:111-115`)
**Issue:** `uint64_t guard = (deadline - guard_origin_half_dots) / 4u + 1024u;` wraps for an origin above the
deadline, giving a near-2^62 iteration guard. A zero-progress `STOPPED`/`OUTPUT_FULL` loop is then effectively
unbounded, which defeats the "bounded public operations" rule. The header says "must not exceed deadline" but
nothing checks it. `replay_diag` currently satisfies it, but the helper is now a shared exported entry point.
**Fix:**
```c
if (guard_origin_half_dots > deadline) return GBB_ACCEPT_STEP_GUARD;
```
and add a case to `acceptance_replay_stop_resume_parity`.

### GR-WR-03: New workflow-policy token and overlay controls are weaker than their stated invariants

**File:** `.github/scripts/verify-workflow-policy.py:140-177` (`SUBJECT_EXECUTION`, `_check_trusted_overlay`), `326-359` (`_check_release_presence`)
**Issue:** Three gaps in controls the fix relies on.
(a) `SUBJECT_EXECUTION` flags only `cmake|ctest|make|ninja` and a `tests/scripts/` path. A step holding `GH_TOKEN`
that runs other tagged-tree code (`python3 -I .github/scripts/x.py` from the subject checkout, a built consumer
binary, `bash build/...`) is not flagged. I enumerated the tokened steps of `candidate`, `candidate-macos` and
`candidate-windows` and none does so today, so this is a gap in the guard and not a live hole.
(b) `_check_trusted_overlay` recognises first use only when the exact path is a word. `cd tests/scripts && bash
verify-release-candidate.sh` or a variable-built path is missed.
(c) The `if` and `step-if` presence items test `fragment in str(if_expr)`, and the mutations only delete the fragment.
`if: env.REUSE_MACOS_CANDIDATE != 'true' || true` or `always() || needs.release.outputs.release_created == 'true'`
would pass while defeating the reuse and release_created guards. Those guards stop a rebuild from replacing
qualified draft bytes.
**Fix:** (a) Invert the rule for tokened steps in subject jobs: allow only `gh`, `jq`, `cmp`, `sha256sum`, `git show
"${GITHUB_SHA}:..."` and inline `python3 -` heredocs, and reject any other external command word. (b) Normalise
path words by basename. (c) Compare the normalised expression exactly, or reject expressions containing `||` when
the fragment is a guard. Add one weakening mutation per guard.

## Info

### GR-IN-01: Windows reserved-name filter omits `CONIN$`, `CONOUT$` and superscript-digit device names

**File:** `tests/scripts/verify-v02-consumers.py:44-51, 294-303`
**Issue:** `WINDOWS_RESERVED_NAMES` covers `CON PRN AUX NUL COM1-9 LPT1-9`. `CONIN$` and `CONOUT$` are also reserved,
and `COM¹/²/³` and `LPT¹/²/³` resolve to devices on recent Windows. The extractor otherwise fails closed (`xb`
open, duplicate check), so this is hardening only.
**Fix:** Add `CONIN$` and `CONOUT$` to the set and compare after NFKC normalisation.

### GR-IN-02: Closeout scan silently skips an explicitly configured but absent `GSD_TOOLS`

**File:** `tests/scripts/verify-closeout-scan.py:40-55`
**Issue:** `runtime_candidates()` appends `GSD_TOOLS` first, but `installed_tools()` just takes the first existing
candidate. A mistyped `GSD_TOOLS` therefore falls back to `~/.claude` or `~/.codex`, so the scan runs on a runtime
the operator did not choose. Identity is verified afterwards, so this is not unsafe, only surprising.
**Fix:** If `GSD_TOOLS` is set and is not a file, raise `ScanError("runtime-unavailable", ...)` without falling back.

### GR-IN-03: `decide()` keeps a published-state branch that production never reaches

**File:** `.github/scripts/verify-published-release-assets.py:126-129`
**Issue:** The comment admits the `release["draft"] is False` branch is exercised only by `--self-test`. It is dead
production code kept for a residual note (P15-09).
**Fix:** Keep, but gate it behind an explicit `--published` flag, or move it into the self-test module, so
production reachability is real.

### GR-IN-04: Brittle numeric regexes tie CTest to control counts

**File:** `tests/CMakeLists.txt:2680-2681` (`controls=2[0-9]`), `tests/acceptance/CMakeLists.txt` (`rejected=[0-9]+/12`)
**Issue:** `controls=2[0-9]` fails at 30 controls and passes for any count from 20 to 29, so it neither pins the
count nor allows growth. The `output_alias` mutant regex accepts any numerator, so it cannot tell "mutant accepted
some aliases" from "mutant accepted all".
**Fix:** Derive the expected count from one constant, or assert `controls>=N` by parsing the number in
`expect_exit.cmake`.

### GR-IN-05: Unbounded blob read and unguarded `cursor` dereference in new helpers

**File:** `tests/scripts/verify-v02-fuzz.py:233-243`, `src/accept/stepper.c:26-30`
**Issue:** `commit_blob` reads an entire `git show` blob into memory with no size bound, against the AGENTS rule to
bound work. `gbb_accept_stop_resumable` dereferences `*span->cursor` and `span->events[...]` with no NULL check on
`cursor`/`events`, although it is documented as safe for a NULL span and sits in the shared header. Current callers
pass validated spans.
**Fix:** Bound blob size (for example 8 MiB, matching the largest fixture) and return false when
`span->cursor == NULL || span->events == NULL`.
