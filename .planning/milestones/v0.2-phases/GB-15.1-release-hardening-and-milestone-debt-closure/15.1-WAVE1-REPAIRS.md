# Phase 15.1 Wave 1 Integration Repairs

These repairs address two integration regressions found by Wave 1's full CTest run.

## Frozen CGB APU producer receipt

The membership checker described an already-recorded producer receipt but compared its source digest with the live `src/core/gabbaboy.c`. That rejected the valid frozen report after later core changes. The report names producer revision `b46bfc9`; its full immutable commit is `b46bfc9e8a6ae5a8bd93d2289445bf5179080443`. The producer core blob at that commit is 240,759 bytes and hashes to `a0a064ac5d0d3fe7221f726bd4525c649636c3c24133293bcac2324a36085d99`, matching the report.

The checker now requires the recorded short revision, reads the pinned Git blob with a 10-second timeout and 2,000,000-byte limit, disables lazy fetch and replacement objects, and checks the receipt digest against those immutable bytes. The historical JSON receipt is unchanged. The current cohort run below is separate regression evidence and does not claim hardware qualification or a new producer receipt.

Before the repair, both `python3 -I tests/scripts/verify-cgb-apu-dispositions.py --membership --build-dir build` and `python3 -I tests/scripts/verify-cgb-apu-dispositions.py --self-test --build-dir build` failed with `core-digest`.

## Acceptance documentation symbol

`docs/game-acceptance.md` used the private name `gbb_accept_drive` in prose scanned as public API documentation. The sentence now describes the acceptance adapter's caller-managed batches directly. The 64-event batch and bounded public queue contract remain stated. `tests/scripts/verify-dense-input.py` required phrases remain unchanged.
