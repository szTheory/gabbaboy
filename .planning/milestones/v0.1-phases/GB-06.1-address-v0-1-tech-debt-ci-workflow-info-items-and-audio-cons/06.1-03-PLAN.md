Header: shebang `#!/usr/bin/env python3`, a docstring explaining the D-07 rule, `from __future__ import annotations`, and stdlib imports only (argparse, json, re, subprocess, sys, time). Constants: SHA_RE = re.compile(r"[0-9a-f]{40}") used with fullmatch; REPO_RE = re.compile(r"[A-Za-z0-9._-]+/[A-Za-z0-9._-]+") used with fullmatch; WORKFLOW_PATH = ".github/workflows/ci.yml"; EVENT = "pull_request".

Pure `decide(sha, listing, fetch_detail, fetch_jobs, required, state)` returns a tuple (verdict, reason, payload), where verdict is one of "WAIT", "PASS" and "FAIL". It follows research Pattern 1 exactly:
(1) If the listing is not a dict holding an int total_count and a list workflow_runs, WAIT "malformed run list".
(2) If total_count > len(workflow_runs), FAIL "run list truncated".
(3) Keep only entries whose head_sha == sha, event == EVENT and path == WORKFLOW_PATH, with int id and int run_number. If none remain, WAIT "no matching run yet".
(4) newest = max(kept, key=run_number). Ordering is by run_number only (research C7).
(5) detail = fetch_detail(newest id). If any of run_attempt, head_sha, event, path or status differs from the list entry, WAIT "list/detail disagree". A persistent disagreement is closed out by the deadline.
(6) If status != "completed", WAIT "newest run <id> attempt <n> is <status>".
(7) If conclusion == "success": jobs = fetch_jobs(id), which uses filter=latest. If jobs total_count > len(jobs), FAIL "job list truncated". For every required name there must be exactly one job with that name, and its conclusion must be "success"; otherwise FAIL naming the job and its conclusion. On PASS, payload = {run_id, run_attempt (run level), job_attempts: {name: job["run_attempt"]}}.
(8) Any other conclusion, including failure, cancelled, timed_out, action_required, neutral, skipped, stale, startup_failure or null: key = (id, detail run_attempt). If state's key equals key, increment state streak; otherwise set streak to 1 and store key. Return FAIL when streak >= 2, else WAIT "debouncing terminal <conclusion>".

Any WAIT result except the debouncing one resets the streak, so failures must be on two consecutive polls. Transport is `gh_get(path, params)`, which runs subprocess.run(["gh", "api", "-X", "GET", path] + ["-f", f"{k}={v}" for each param], capture_output=True, text=True, check=False). It never routes through a shell and never builds a jq expression from the SHA. A non-zero exit or invalid JSON raises a TransientError, which the loop reports as WAIT. Paths: f"repos/{repo}/actions/workflows/ci.yml/runs" with params head_sha, event=pull_request and per_page=100; f"repos/{repo}/actions/runs/{run_id}"; f"repos/{repo}/actions/runs/{run_id}/jobs" with params filter=latest and per_page=100.

`run_gate(sha, repo, required, deadline_seconds, interval_seconds, clock, sleep, fetchers, github_output, attempt_job)` polls until PASS or FAIL, or until clock() passes start + deadline. At the deadline it prints the legacy deadline message and returns 1. On PASS with github_output set, it appends `run_id=` and `run_attempt=` lines, taking the attempt from payload job_attempts[attempt_job] (research Pitfall 3: the artifact is named with the attempt in which macos-player-package ran).

main(): argparse with --self-test (store_true), --sha, --repo, --require (append), --deadline-seconds (int), --interval-seconds (int, default 10), --github-output and --attempt-job. Validate the SHA and repo before any fetch, returning 2 with a message on rejection. Require that --github-output and --attempt-job are given together and that --attempt-job is among --require.

In this tracer task the self-test needs only three canned cases: newest success -> PASS, older success with the newest in progress -> WAIT, and invalid SHA -> exit 2 with no fetch call. Task 2 expands the table.
