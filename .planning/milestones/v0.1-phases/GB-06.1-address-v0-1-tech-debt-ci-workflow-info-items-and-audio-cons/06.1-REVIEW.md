## Info

### IN-01: Player-specific failure message is effectively unreachable

**File:** `.github/scripts/wait-exact-head-ci.py:201-205` (and `:181-183`)
**Issue:** `legacy_message` prints "Required player package job failed..." only when the FAIL payload carries `failed_job == attempt_job`. That payload exists only on the `conclusion == "success"` branch. In the real workflow, `required-native` depends on `macos-player-package`, so a failed player job makes the whole run conclude `failure`. That run takes the debounce branch, whose payload has no `failed_job`. The player-specific diagnostic the old inline script printed therefore never appears in practice; the generic message prints instead. Failing closed is unaffected. Only the diagnostic regressed, and the self-test (`_gate_case_player_failure_message`) passes only because it fabricates a run with conclusion `success` plus a failed job.
**Fix:** On a non-success terminal conclusion in player mode, fetch the jobs and name the failed required job in the payload. Alternatively, drop the unreachable branch and its synthetic test so the self-test does not imply coverage that real runs cannot reach.

### IN-02: Missing job `run_attempt` is written to GITHUB_OUTPUT as the literal "None"

**File:** `.github/scripts/wait-exact-head-ci.py:184,222-228`
**Issue:** `job_attempts[name] = job.get("run_attempt")` is not validated. If the API ever omits the field or returns a non-integer, `run_attempt=None` is written to `$GITHUB_OUTPUT`. The artifact download then fails later with a confusing name mismatch instead of the gate failing or waiting on malformed data, as it does for other malformed fields.
**Fix:** In the required-job loop, treat a non-int job `run_attempt` like other malformed data, e.g. `if not isinstance(job.get("run_attempt"), int): return _wait(state, "job {} lacks run_attempt".format(name))`.

### IN-03: New `close()` failure path in `read_rom_file` is untested

**File:** `src/player/session.c:143-152`
**Issue:** The reordering that gives close failure its own message ("Could not finish reading the selected ROM.") has no test. The 2 MiB bound tests cover only the size branch. The change is small and correct by inspection. This is a coverage note, not a defect.
**Fix:** Optional. Cover it with a link-time `close` interposer in the test, or accept it as untestable without fault injection and note that in the test comment.
