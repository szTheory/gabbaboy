<decisions>
## Implementation Decisions

The owner asked for a multi-lens fan-out with an adversarial pass, then one coherent set of recommendations to follow automatically. The decisions below are that synthesis and are locked.

### Audio consumer coverage
- **D-01:** Add a self-contained `audio_api_smoke()` to `tests/consumers/cpp/main.cpp` and, for symmetry, to `tests/consumers/c/main.c`.
  - Follow the existing `battery_api_smoke()` pattern: an in-source 32 KiB ROM-only image with a valid header checksum, no fixture file, and `goto done` cleanup.
  - These binaries already run as `installed_consumer_{c,cpp}` and `installed_consumer_phase2_{c,cpp}` on native-linux, native-macos and **native-windows-x64**. That satisfies criterion 2 with no new job, no new CTest name and no `tests/expected-tests.txt` change.
  - The C++ path also exercises the `extern "C"` header and the MSVC import/export surface.
- **D-02:** No Windows job is added to `preview.yml`. Windows archive-level `preview_package_smoke` parity is re-deferred with this reason: "the Windows installed-consumer lane supplies the audio coverage the audit named; archive-level Windows smoke needs zip/path handling in `PreviewPackageSmoke.cmake` and a new required check, which is out of v0.1 scope."
- **D-03:** Assertions are structural and self-consistent only. Never pin a digest literal.
  - **Program:** use the `tests/test_audio.c` audio-tracer program (NR12/NR11/NR13/NR14 writes, then `JR -2`).
  - **Run result:** `gbb_run_audio` for 140448 half-dots must report `GBB_STOP_BUDGET` and consume the full budget.
  - **Frame count:** it must equal the header formula (`budget*48000/8388608`, which is 803). Derive every number from the public header and `test_audio.c`.
  - **Activity bounds:** reuse the non-zero-sample and transition bounds from `test_audio.c`.
  - **Capacity and sentinel:** a NULL/0 capacity behaves as the header defines. Frames past `n` keep their poison value.
  - **Determinism:** compute FNV-1a over the frames of two fresh instances in the same process and require equal values.
  - **`gbb_reset`:** must return `GBB_OK`, and the re-run must produce the same count and stop result. Assert hash equality after reset **only if** research confirms that `gbb_reset` clears APU state. Otherwise leave that assertion out and record why.

### Info-item triage
- **D-04:** Fix all seven items. Re-defer an item only if its fix fails its own evidence gate, and record the reason and the revisit trigger in the phase report. The workflow batch already makes most phase reports stale, so re-deferring saves nothing and lets the debt pile up.
- **D-05:** Per-item approach:
  - **P1 IN-01:** delete the unreachable `PLAYER_REQUESTED`/optional branch in the `preview.yml` aggregate. Require player `success` unconditionally, since `preview.yml` triggers only on `pull_request`, and remove the word "optional".
  - **P1 IN-02:** see D-07 and D-08.
  - **P2 IN-01:** use a single source of truth for the pull-request player gating in `ci.yml`. Preserve the semantics exactly: a push accepts a skipped `macos-player-package`, and a pull request requires `success`. Job names and required contexts stay unchanged.
  - **P3 IN-01:** in `src/player/session.c` `read_rom_file`:
    - Split the close-failure branch from the size-bound branch and give it its own accurate message.
    - Add `O_NOCTTY` alongside the existing `O_NONBLOCK`. Keep both, because they solve different problems. The player builds only on POSIX/macOS.
    - Evidence: the existing oversize test keeps the "2 MiB" message, and the 51 player tests stay green. The close-failure path has no cheap injection point, so its evidence is inspection, which must be stated honestly.
  - **P3 IN-02:** extract one receipt-fields helper in `tests/scripts/test_verified_player_output_dir.py`. Re-defer instead if the extraction would change assertion text or grow past about 30 lines. Run a mutation check to show a field flip still fails.
  - **P3 IN-03:** add a test that forces the **inner** withdrawal site to fail and asserts the original publication error is not masked. The suite count rises by one. Update the inventory only if it tracks these sub-tests.
  - **P5 IN-01:** resolve by documentation, with behaviour unchanged.
    - Add a comment at the `tests/scripts/verify-phase3-player.sh` default explaining that CI always sets `GBB_VERIFIED_OUTPUT_DIR` and that local shared-`/tmp` use should set it too.
    - Do not switch to `mktemp -d`. That would change a release-path script for a local-only concern, and the helper's no-follow open and fixed-name unlink already contain the risk.
    - The disposition row should say "fixed (documented)" rather than claim a behaviour fix.
- **D-06:** `.github/workflows/release.yml` is not touched, so the frozen v0.1.0 evidence in the Phase 6 report stays valid.

### IN-02 exact-head lookup
- **D-07:** The newest same-SHA run decides.
  - Select the newest `ci.yml` `pull_request` run for the exact head SHA by `(run_number, run_attempt)`.
  - Wait while it is not completed, and fail only when that newest attempt completed without success, including when its required jobs did not succeed.
  - Never accept an older success. A newer failure is never ignored.
  - Fail closed if the run list is truncated (`total_count` > listed), if list and detail disagree after re-polling, or if the deadline passes. Keep the current deadlines.
  - Apply a two-consecutive-poll debounce before the final failure to absorb stale reads right after a re-run.
  - Validate the SHA against `^[0-9a-f]{40}$`.
  - Required jobs are `required-native`, plus `macos-player-package` for the player job.
  - Rejected alternatives:
    - Accepting any same-SHA success would weaken exact-revision evidence, because `refs/pull/N/merge` drifts.
    - A `workflow_run` trigger or reusable workflow would change how required checks are attributed.
- **D-08:** Replace the three inline poll loops (Linux, macOS and player jobs) with one in-repo script under `.github/scripts/` that has a `--self-test` mode using canned list and detail JSON.
  - The script is first-party and adds no dependency, which matches the existing `.github/scripts` pattern. Drift between the inline copies is what caused IN-02.
  - Prefer Python 3 stdlib or bash+jq+gh, whichever matches what the runners already use. No new third-party action.
  - Run the self-test in CI next to the existing script self-tests.
  - Self-test cases: an older failed run with the newest in progress (wait); newest succeeded (pass); newest failed after an older success (fail); attempt 2 in progress after attempt 1 failed (wait); wrong SHA, event or path is filtered out; a missing required job (fail); a truncated list (fail); an empty list (wait); a list/detail attempt mismatch (wait); cancelled, timed_out or action_required (fail).
  - Research must confirm the `run_attempt`, re-run and list-ordering semantics against GitHub's REST docs before planning locks the predicate.

### PR and re-verify shape
- **D-09:** Use two PRs.
  - **PR 1 (code and workflow):** consumers, player and test scripts, plus **one commit** that edits `ci.yml` and `preview.yml` together, which is the single batched workflow change. Add the new `.github/scripts` gate script and its CI self-test wiring.
  - **PR 2 (refresh):** a docs-only refresh PR cut from the exact merged main head.
  - This follows the #47–#53 precedent. Branches are fresh, and `gsd/phase-*` names are never reused (GB-GSD-009).
  - Merge only after all required contexts (`required-native`, `fixture-repro`, `preview-package-smoke`) pass on the exact PR head, with `strict` branch protection. Read back the main-push runs for the merged SHA.
- **D-10:** Measure the re-verification set rather than predict it.
  - After PR 1 merges, run `gsd-tools verification status <phase-dir>` for every phase. Refresh exactly the stale ones, in order 1→6. Phase 5 regenerates its own planning docs before its VERIFICATION, as in #48.
  - From the covered inputs, expect all six phases to go stale:
    - **Phase 1:** ci, preview and the consumers.
    - **Phase 2:** ci.
    - **Phase 3:** ci, preview, `session.c` and the scripts.
    - **Phase 4:** `session.c` and the consumers.
    - **Phase 5:** preview, `session.c` and the scripts.
    - **Phase 6:** ci and the scripts.
  - This is accepted. It is the one-time cost the phase exists to pay.
  - Run `git grep -nE '^(<<<<<<<|>>>>>>>) '` before committing (GB-GSD-010), then confirm every phase reads `passed` and fresh on committed main.
- **D-11:** PR #41 (release-please 0.1.1) is out of scope. Do not approve its runs, do not merge it during 06.1, and make no release bump. If anything merges to main between PR 1 and PR 2, rebase the refresh branch and re-measure staleness.

## Existing Code Insights

### Reusable Assets
- `battery_api_smoke()` in both installed consumers is a template for an in-source ROM image with sentinel, poison and `goto done` cleanup.
- The `test_audio.c` audio-tracer bytes and bounds give known-good structural expectations.
- Self-test scripts under `.github/scripts` and `tests/scripts` (`--self-test` with mutation checks) are the pattern for the new gate script.

### Established Patterns
- Exact-head evidence: the preview gate must never certify a wrong revision, and it fails closed.
- Aggregate jobs (`required-native`, `preview-package-smoke`) are the required contexts. Their names must not change.
- Staleness is digest-based on the covered files in each VERIFICATION frontmatter. Refreshes go in docs-only PRs from the merged head.

### Integration Points
- `ci.yml` jobs native-linux, native-macos and native-windows-x64 run the installed consumers through CTest inventory verification.
- The new gate script is called by the Linux, macOS and player jobs in `preview.yml`. The checkout step must precede the gate step.
