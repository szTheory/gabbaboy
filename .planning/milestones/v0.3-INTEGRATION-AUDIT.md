### In-Scope Exports and Consumers

- `gbb_state_size`, `gbb_save_state`, `gbb_load_state`: called by both installed C/C++ consumers and the Phase 18 slot engine; not merely declared.
- `gbb_get_input_clock`: read by slot scratch validation and by the success result used for input reanchoring; the reanchor is applied by the SDL event path.
- `gabbaboy_host` / `gbb_host_main`: `gabbaboy-runner` dispatches into it; the target is SDL-free and consumes the public core API.
- `host_save_io_read_bounded` / `host_save_io_replace`: used by the player slot store and host runner; atomic writer failures and rollback are exercised.
- `host_save_format_lookup`: used by `--print-save-format`; its JSON table is installed beside the runner and checked against produced save bytes.
- `state_raw_to_host`: called by both validation's non-failing field store and final apply; the Phase 19 review change has an active caller on each path.
- `release-evidence-lifecycle.sh`: called by production workflow steps and executed by the local replay checker; no lifecycle export is only a dead test helper.

No in-scope API export is orphaned. The broader phase summaries contain many checker/helper exports; their required registrations and workflow consumers are covered by phase verification and the current release/readback checks rather than treating every helper as a product API.
