## Execution contract

Same contract as 18-01 (registration in `tests/cmake/host.cmake`, append-only `tests/expected-tests.txt`, POSIX-only names in BOTH Windows lists plus `verify-test-inventory.sh --self-test`, dirty-list update for every new `src/host` file, feature macros per POSIX file, `python3 -I` stdlib scripts loading `host_fixture.py` via importlib, base 60 s TIMEOUT). Cadence is never tested by waiting: debug emulation costs ~3-4 ms per frame, so a 3,600-frame end-to-end wait is 11-14 s plain and ~3x under ASan (RESEARCH Pattern 5, GB-CI-012). Every end-to-end run in this plan uses at most 400 frames. Mutant runners are build-tree executables only; nothing mutated is installed. No package installs (T-18-SC).

Windows build rule (18-01 execution contract, checker B-3), applied here: `host_save_io_sweep` and the `GBB_HOST_TESTING` seams live in host_save_io.c's `#ifndef _WIN32` body; the `_WIN32` build defines `host_save_io_sweep` as an ISO C stub returning `HOST_IO_EREAD` (Windows refuses host mode before it is reachable). `host_cadence.c` is pure ISO C with no guard. `gabbaboy_host_testing` is created inside `if(BUILD_TESTING)` AND `if(NOT WIN32)`; `test_host_save_io`, every `gbb_host_mutant_runner` executable and every mutant library whose tests are POSIX-only are created inside `if(NOT WIN32)` in tests/cmake/host.cmake, next to their `add_test`. `test_host_cadence` and the two cadence mutant libraries stay portable (pure code, MSVC compiles them) and their tests run on Windows.
