## Public API, runner, player, and installed-consumer trace

There is no HTTP-route inventory to report. The primary exported boundary is `include/gabbaboy/gabbaboy.h`: ROM load, emulation/run, ROM probe/info, RGB555 frame copy, battery state, and RTC catch-up functions. The core implements those operations in `src/core/gabbaboy.c`; mapper/profile/timing/rendering remain behind this API. `src/runner/main.c` calls the create/load/run boundary for scripted acceptance and corpus cases. `src/player/main.c` uses probe/info for model selection and the RGB555 frame path; `src/player/session.c` and `src/player/catch_up_policy.c` connect battery/RTC state to reopen behavior. `tests/consumers/c/main.c` and `tests/consumers/cpp/main.cpp` compile against the installed public headers/library and execute profile, probe/info, frame, RTC and other boundary checks via `cmake/RunInstalledConsumer.cmake`. Phase 15 packages their results and release workflow readback validates the exact published consumer receipt.

No key exported API in this required scope was found to be orphaned from the runner, player, test consumer, or release evidence. No route/auth finding applies.

## Findings and technical debt

**Integration blockers: 0.** No expected connection is BROKEN. **Warnings:** Phase 15 review retains eight WARNING and eight INFO advisories. They are real release-evidence/tooling hardening debt and should not be mistaken for broken v0.2.0 user flows.

Open Phase 15 WARNING advisories:

- WR-01: tagged-source evidence jobs use a `contents: write` token.
- WR-02: source-archive receipt can be checked without binding the archive to the Git tree.
- WR-03: fuzz receipt validation is self-attested/shape-only.
- WR-04: the performance regression gate cannot fail because the note is prewritten as a constant.
- WR-05: workflow assumes GitHub tarballs are byte-identical across downloads.
- WR-06: trusted overlay covers only three validators while the tagged gate delegates to other validators.
- WR-07: DMG KEY1 fuzz scenario 3 and its seeds are weak.
- WR-08: consumer receipt `source_sha` is self-reported by the package. The fresh live readback binds the current published consumer receipt hash and installed-prefix digest, but the release validator still has this independent source-binding limitation.

Open Phase 15 INFO advisories:

- IN-01: check-recovery/decide is not wired into the workflow.
- IN-02: some workflow checks use substring matching.
- IN-03: `--evidence-only` skips digest checks when artifacts are absent.
- IN-04: archive-tree validation does not cover file modes/symlink depth.
- IN-05: curl max-filesize handling may be incomplete for chunked transfers.
- IN-06: delivery checks bind SHA/success but are not workflow-enforced.
- IN-07: release and rehearsal scripts duplicate logic.
- IN-08: broad LF globs and hard-coded case counts can age poorly.

These findings map primarily to SHIP-09/SHIP-11 release evidence and workflow integrity; WR-08 also affects SHIP-10 consumer source binding, while WR-07 concerns the fuzz evidence used for SHIP-11. P15's review remains **0 critical, 8 warning, 8 info, all open/advisory**.
