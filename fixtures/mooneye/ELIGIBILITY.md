# Mooneye CPU/timer candidate eligibility audit

## Immutable identity and rights

Source is Mooneye Test Suite commit `31510e12eea6286d36eea060a6adde755e1067aa`, tree `2b8c52424a49a2a7466cf631fd8992c53d0de2fa`. The source and helper files carry the upstream MIT notice, retained in `LICENSE.txt`; the candidate patch retains those headers. WLA-DX is the separately pinned GPL-2.0-or-later build tool in `SOURCES.md`, not part of the ROM. The upstream Darkrose `common/font.bin` has no supplied redistribution license. Preparation substitutes only the documented 2032-byte zero asset from `font-source.c`, digest `23ba65cb93433b65e7ddcae5f8a7dd2ca232491793848644e625875c6dd6ae43`; see `FONT-LICENSE.txt`.

## Source and execution closure

The three acceptance roots are `acceptance/instr/daa.s`, `acceptance/timer/tim00.s`, and `acceptance/timer/tim00_div_trigger.s`. Each includes `common.s`, which includes `hardware.s`, `macros.s`, and the exact `common/lib/*.s` list in its `manifest.json` `source_closure`. `common.s` also includes `font.bin`. No root includes other files directly. Its header selects `.romdmg` by default, jumps from `$100` to `$150`, and enters the test with boot ROM skipped; none of the three roots asserts boot-state or CGB behavior. Each source explicitly declares pass on DMG hardware. DAA compares all table-defined DAA output and flag cases. The two timer roots compare sampled TIMA values with independent source constants `$04` and `$05` after controlled DIV/TAC operations. There is no PPU read in the assertion bodies.

All three **original upstream-built ROMs are ineligible as built** for this phase's CPU/timer-only core. Both timer roots run `setup_assertions`, set expected D/E, then `quit_check_asserts` selects `check_asserts_cb`. DAA uses `quit_ok` after both table loops, or `quit_inline` from its real mismatch branch. Both macro paths jump to `quit`, which calls `is_ppu_broken` **before** invoking the callback. `is_ppu_broken` reads LY (`FF44`). The original `quit` can then call `disable_ppu_safe`, `reset_screen`, and `print_load_font` (LCDC/PPU registers and VRAM); it passes HL=`$9800` to printing callbacks, then reads LY again and waits on LY during post-callback reporting. These accesses make even an otherwise correct assertion result depend on missing PPU behavior. A generic unsupported-read fallback cannot qualify these original ROMs.

The admitted source-only derivative modifies only harness `common/common.s` and `common/lib/quit.s`: it removes PPU-only included helper sections and the unused font section, invokes the original callback directly with a WRAM print pointer (`$c000`), then preserves returned D status. The timer callback's original `check_asserts_cb` still compares saved registers with source constants and returns D=0 for pass or nonzero for failure. DAA's original inline callbacks still set D=`$00` or `$42` after the table checks. The unchanged `quit` verdict maps D=0 to B,C,D,E,H,L=`03 05 08 0d 15 22` and nonzero D to six `$42` bytes, then executes the original `magic_breakpoint` (`LD B,B`, opcode `$40`). Serial handling follows the breakpoint. Candidate probes confirmed zero PPU bus accesses before the result breakpoint.

The derived source is **not** an untouched upstream hardware ROM. Plan 02-17 admitted only this pinned derivative after source/rights review, positive and induced-negative protocol probes, and exact local/hosted byte identity. The original manifest and original three ROM blob hashes remain captured in `pre-admission-baseline.json`; the admitted denominator remains exactly one CPU and two timer cases. This fixture admission does not complete CPU-05: Plan 02-16 still owns strict runner/inventory and phase-level verification.

## Deterministic candidate linker recipe and hosted qualification

The pinned WLA-DX 5.22 linker is invoked with `-nS -d -S` for derived candidates. Its `-nS` option places sections in their order of appearance, avoiding the invalid equal-priority/equal-size comparator passed to `qsort` by the default linker path. The tool's `doc/linking.rst` documents this input-order behavior. No source patch is applied to WLA-DX; the tool revision, source tree, archive digest, versions, harness patch, font source, replacement-font digest, upstream acceptance-source digests, and exact flags are recorded in `candidate-digests.json` and each reproduction's `inputs.txt`.

On Darwin/arm64, two complete pinned builds produced byte-identical 32,768-byte candidates: DAA `3a39eda77a09b817e4e38004a3d117990565fb797e8a4f470920f1b7608f0a08`, TIM00 `476b2332de3f2d6604f8e1478daa8cbc7c59c89c50837fd47cc95e96e784d4f7`, and TIM00 DIV trigger `566da853858061c69866c47cc31b85b1fef003d4c088c8e8dbb26973da9944da`. At exact pushed source revision `93647ac98b7f8437cc9640e3dec437bba4f11e9c`, hosted Linux/x86_64 run [37561292904](https://github.com/szTheory/gabbaboy/actions/runs/37561292904) reproduced all three byte arrays exactly. Protocol probes, provenance, source closure and redistribution notices passed. The resulting manifest SHA-256 is `98a1799b8be9c022ac13467a552890fb12bdd706017e42e12c944ec618d60527`; the exact outputs and admission record are in `candidate-digests.json` and `manifest.json`. The eligible denominator remains one CPU and two timer cases. The historical original-ROM bytes and raw manifest remain separately bound by `pre-admission-baseline.json`.

## Candidate overlay and local probe evidence

`headless-report.patch` SHA-256 is `c3679ab53b59da14a0f6af1fdd552316ba922762c3a91988f7f8ac4440516e5d`. It changes only the two MIT-covered harness files. In `common/common.s`, it removes seven PPU-only helper includes (`clear_oam`, `clear_vram`, `disable_ppu_safe`, `is_ppu_broken`, `print_load_font`, `reset_screen`, `wait_ly_with_timeout`) and the unused font section. All acceptance roots, constants, callback code, print helpers, and register result protocol remain unchanged. In `common/lib/quit.s`, it removes the first PPU probe/setup, changes the callback's print pointer from VRAM `$9800` to WRAM `$c000`, and removes the post-callback LY/vblank wait and its matching D stack save/restore. The callback is still called via the original stack-return mechanism, its returned D is tested without alteration, and the original success/failure register assignments and `magic_breakpoint` remain. `macros.s` retains unused PPU macro definitions; they are not invoked on these candidate paths. The substituted font is generated and pinned by the reproduction recipe but is no longer included in the candidate ROM.

An earlier local candidate/probe run recorded different byte digests under the default linker ordering; those outputs are superseded by the pinned `-nS` recipe above. The current admitted outputs are DAA `3a39eda77a09b817e4e38004a3d117990565fb797e8a4f470920f1b7608f0a08`, TIM00 `476b2332de3f2d6604f8e1478daa8cbc7c59c89c50837fd47cc95e96e784d4f7`, and TIM00 DIV trigger `566da853858061c69866c47cc31b85b1fef003d4c088c8e8dbb26973da9944da`. The final positive and induced-negative probes reached the original source callbacks and symbol-addressed `LD B,B` breakpoint with zero PPU bus accesses. The induced control changes only one byte in a private DAA copy and yields the expected six-`0x42` failure result. These are bounded protocol probes, not complete CPU-05 runner qualification; Plan 02-16 owns that remaining evidence.
